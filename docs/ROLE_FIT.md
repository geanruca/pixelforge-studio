# Fit with the role

What the [Senior Product Engineer post](https://docs.google.com/document/d/12VIa7syPDk6LYNlv5OR6VxYvfMZ8iMKVZI1u_xhPzHM)
asks for, and where this repository shows it. Where the repository cannot show something, it says so.

## What the post asks for

| The post says                                                                                                                                   | Shown here                                                                                                                                                                                                                                                                                                                        |
| ----------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "Some of your code will calculate prices users pay for AI generations. This requires a high degree of accuracy, otherwise we could lose money." | Integer nanodollars, no floats in any amount. On the live deployment our recorded provider cost equals `GET /v1/usage` to the nanodollar, and the ledger adds up to the balance. Three independent guards against charging twice. See `app/Support/Money.php`, `app/Services/Credits/CreditLedger.php`, `tests/Feature/Credits/`. |
| "I'd like to feel safe merging your code without reviewing it."                                                                                 | 276 tests, run on SQLite and PostgreSQL. PHPStan level 9 with no baseline. CI on every push. A contract test keeps the API and its documentation in step. An independent review was run on the money paths and its findings fixed with tests.                                                                                     |
| "Take vague and loosely defined features, ask useful questions, implement it, test it."                                                         | The brief leaves sub-cent handling, the estimate and failure behaviour open. Each was decided, written down with its reason and tested: see "Decisions I would defend" in the README and the [engineering notes](https://pixelforge.24.199.64.10.sslip.io/engineering).                                                           |
| "…and investigate problems after release."                                                                                                      | The first live run showed an overloaded request being retried every two seconds for fifteen minutes. It was diagnosed from production logs, fixed with exponential backoff and a stop, tested and redeployed (commit `a2ef4d0`). The operations panel exists so the next investigation starts from data.                          |
| "Create the most intuitive … tool UIs" / "strong product sense"                                                                                 | The price is visible before, during and after. Waiting shows what is happening instead of a spinner. Missing details are asked for in context. Failures say in plain words that nothing was charged. Keyboard, screen reader and reduced-motion support throughout.                                                               |
| "Help make our codebase easier to maintain."                                                                                                    | One class per responsibility with the reason written where the next reader will look. A provider contract instead of a vendor client. One state machine instead of three handlers. A map of the code in the README.                                                                                                               |
| "Self-motivated … high attention to detail."                                                                                                    | The requirements checklist maps every requirement and edge case of the brief to a test, and a second list holds the standards added on top of it.                                                                                                                                                                                 |
| "Tech stack: Laravel, Vue, Inertia, Tailwind, Postgres."                                                                                        | All five, at current versions: Laravel 13, Vue 3, Inertia 3, Tailwind 4, PostgreSQL.                                                                                                                                                                                                                                              |

## Nice to have

| The post says                                                                                                  | Shown here                                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "DevOps or infra engineering … ffmpeg in queue workers, which doesn't work on Laravel Vapor or Laravel Cloud." | The app is deliberately not on a serverless platform. It runs on a VPS provisioned through the Forge API: nginx, PHP-FPM, supervised queue workers on separate queues, a scheduler, PostgreSQL and TLS, with push-to-deploy. Long-running or binary-dependent workers such as ffmpeg fit that shape. **Not shown:** EKS or ECS. |
| "We're looking to add ClickHouse … for product analysis."                                                      | **Not shown.** The ledger and the webhook events are append-only streams, which is the shape an analytical store ingests well; the README lists it as a next step.                                                                                                                                                              |
| "Typesense, AWS."                                                                                              | **Not shown.** The app has no search, and storage is a local disk behind a configurable Laravel disk, so S3 is a configuration change.                                                                                                                                                                                          |
| "Video editing tools … DaVinci Resolve Extension built on Electron."                                           | **Not shown** in this repository.                                                                                                                                                                                                                                                                                               |
| "Maybe you have some skills you think we could gain from."                                                     | A REST API with an OpenAPI contract and an MCP server, so AI agents can use the product through the same rules as people. Resilience patterns around a third-party AI provider: circuit breaker, idempotency, backoff, fair scheduling.                                                                                         |
